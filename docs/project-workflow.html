How llmtie-rs works

A from-scratch Rust engine for a Taiwanese Hokkien (Taigi) voice assistant. It reads published checkpoints directly, owns its CUDA arithmetic, and can run an entire spoken conversation as one binary—or distribute the same stages over HTTP.

01 · Conversation workflow

Speech enters; Taigi speech leaves.

The browser streams microphone audio to the serving layer. VAD prevents noise from reaching recognition; ASR transcribes speech; a chat LLM produces a response; the translator makes POJ Taigi when the reply is not already direct Taigi; and a selected synthesiser returns WAV chunks for gap-free browser playback.

Deployment is a configuration, not a fork. Each stage takes either --<stage>-model PATH to run locally or --<stage>-url URL to call a worker. The serving code cannot tell which choice was made, so the same binary supports a monolith, individual workers, and mixed topologies.
02 · Architecture

Strict layers, narrow boundaries.

The workspace separates model geometry from arithmetic. Low-level containers never interpret a tensor; schemas validate every name, shape and type before computation; CUDA receives only flat slices and dimensions; the engine alone wires stages together.

Design constraints that shape the code
Reject early.
A wrong tensor geometry fails while loading, naming the tensor—not after it produces plausible but wrong audio.
Map safely.
Mapped bytes are never cast to f32 without an alignment proof.
Reference every kernel.
Each numeric CUDA kernel has a CPU twin and a differential test.
Capture, don’t transcribe.
The framework reference creates intermediate golden tensors; expected values are never hand-written.
Why ASR and translation are CUDA-only

A scalar Whisper encoder would take about twenty minutes per 30-second utterance. The 13B translator is 26.5 GB in f16 but would need 53 GB in f32 for the scalar path. Both are refused on CPU at preflight. Their constituent kernels still have CPU differential references; the assembled stages are checked directly against captured oracles.

Container contract and quantised weights

The three readers are sibling crates: safetensors, GGUF and modern Torch state-dict .pth. They provide validated addressing without a shared trait. For Llama GGUFs, Q4 through Q6 packed blocks can remain packed in VRAM and are unpacked inside the integer matmul; a quantised checkpoint therefore occupies approximately its file size on the card. Unsupported Torch object graphs are refused rather than executed.

04 · Inside the models

What each model actually computes.

These are the inference paths implemented by the project—not generic descriptions of the model families. Training-only components are deliberately omitted where the published checkpoint makes them irrelevant to synthesis.

VITS / Coqui VITS — text to waveform

1. Normalise & tokeniseMMS VITS lowercases NFC POJ, drops unsupported symbols, then intersperses blank id 0. Coqui consumes IPA instead.
2. Text encoderEmbedding → six relative-position attention / convolution FFN blocks → prior mean and log-scale.
3. Duration and alignmentA stochastic duration flow predicts each symbol duration; length regulation expands the prior into acoustic frames.
4. Generate speechFour coupling blocks run in reverse to obtain latent z; HiFi-GAN then upsamples 256× through four stages and multi-receptive-field resblocks.

The MMS decoder uses 8 × 8 × 2 × 2 upsampling to produce 16 kHz. Its posterior encoder is training-only and is never uploaded for inference.

Breeze-ASR-26 — speech to text

1. GateSilero VAD turns 512-sample (32 ms) windows into probabilities, then an hysteresis segmenter identifies a speech turn.
2. FrontendThe audio crate computes a 80-bin, Slaney-normalised log-mel spectrogram from 16 kHz PCM.
3. EncoderTwo convolutional stem layers reduce 3000 mel frames to 1500 positions; 32 Whisper transformer layers encode the fixed 30-second window.
4. Greedy decoder32 decoder layers use self KV cache plus cross-attention cache over the encoder. The next token is selected greedily; no beam search, temperature fallback or timestamp path is run.

Translator and chat — token to token

1. Tokenise & prefillSentencePiece (translator) or Llama byte-level BPE (chat) creates the prompt. Tiled integer matmul processes all prompt rows and fused attention avoids materialising score matrices.
2. Decode one tokenRMS norm → packed-weight / int8-activation mat-vec → RoPE → f16 KV-cache append → fused decode attention → gated MLP. Projection tails absorb residual and normalisation seams.
3. Sample or stopChat samples a streamed completion and checks stops; the translator uses its exact [TRANS] template, repetition penalty and stop string to emit POJ.
4. Share weight trafficFor up to four clauses, translator decode batches rows: every packed weight byte is fetched once per step while each sequence keeps its own KV cache.

Chat has grouped-query attention (32 query / 8 KV heads). The translator has 40 / 40 heads, so its KV cache grows much more quickly with context.

CosyVoice3 and Tacotron2 — alternative speech paths

CosyVoice speech LMText and voice-conditioning inputs generate discrete speech tokens with a Qwen2-derived 24-layer, 14-query/2-KV-head model.
CosyVoice flowA 22-layer DiT runs 10 Euler denoising steps over both classifier-free guidance rows as one batch; the result is an 80-bin, 50 Hz mel.
CosyVoice vocoderF0 and harmonic excitation feed a causal HiFT network; its output head predicts iSTFT magnitude and phase for 24 kHz audio.
Tacotron2 + WaveGlowLocation-sensitive attention emits mel frames autoregressively; WaveGlow transforms noise into waveform. Its legacy object-graph checkpoint is converted once, offline.

06 · Correctness before speed

Speech that sounds plausible is not accepted as proof.

Oracle-driven development loop

  1. The reference implementation runs with fixed stochastic seeds.
  2. Intermediate tensors are captured under .golden/, with checksums.
  3. Rust loader/schema rejects incompatible weights at bind time.
  4. CPU reference and CUDA kernel are differentially compared using max-absolute error and cosine similarity.
  5. Whole-stage and end-to-end results are compared before a performance change is accepted.
A green CI tick is deliberately modest. Public CI validates compilation, formatting and linting but has no checkpoints or GPU. Model tests print SKIP: when assets are absent; skipped is never considered passed.
